## 16:56 录屏对应日志：正文超时与低缓存等待

后续收到的两份日志对应正常可打开首页的上一轮测试。1080P 高码率视频在约 21 秒处出现视频范围请求 `0xC00D4278`，加速器已经 `bypass=True`，播放器先在约 0.4 秒缓存处进入补缓冲暂停。随后缓存仅增加至约 1.7 秒，未达到三秒恢复门槛。该轮没有索引格式错误，也没有画质切换；不能沿用前一个案例的索引错误解释。

代码确认：快速原生恢复只在终结性的 MediaFailed 处理加速正文错误，非终结性的 DownloadFailed 仍交由原生管线继续重试；同时，少量局部缓存增长会重置十二秒进展看门狗。这使已经失败的加速源长期占据补缓冲等待。另一个缺口是重新创建原生源时使用页面保存的旧 CDN 偏移，可能丢失 DownloadFailed 已选好的备用线路。

本轮将已知正文失败与实际低缓存等待结合：未被暂停、定位或弹窗阻止，且等待中的有限缓存低于三秒时，立即按本次观看最多一次恢复原生下载，保留画质、位置和当前备用线路。已有大量可播缓存时继续播放，不因 bypass 标记而清空缓存。新增诊断 `routeOffset`、`bodyFailed` 便于核对恢复原因。没有把正常按需下载的空闲期当作断网，也不以数字平滑代替真实缓冲进展。海外线路实际吞吐仍受 CDN 与网络条件影响。

同次发现数字安装版本 `1.0.27.0` 的独立启动回归：直播图片行仅由运行时 XAML 引用，.NET Native 未生成自定义控件元数据，创建首页报 `0x802B000A`。改为 App.xaml 编译模板后，已经在实际桌面 UWP 激活中验证首页启动与直播聊天导航。启动探针现在会拒绝进入启动错误页的包；构建成功不能代替此项检查。

## 后续实机日志：索引解析失败

15:02 录屏对应的日志已于 2026-11-17 收到。最新一轮 4K 轨道为 HEVC、3840×2160、SDR，接口帧率 59.937；不是 HDR 输出模式。视频初始化的 1108 字节成功接收，随后 2936 字节索引返回 HTTP 206，但原生 IndexSegment 解析报 `0xC00D36BE`（`MF_E_INVALID_FILE_FORMAT`）。切换回原生下载后仍重复同一错误，随后出现无有限范围的媒体请求、HTTP 200 和 `0xC00D4278`（`MF_E_NET_TIMEOUT`）。最后仍停在 Opening、12 秒、可播缓存 0，76 次下载失败。加速器在此之前未接管任何媒体范围，不能把这条故障归结为并发下载或 HDR 解码。

本次增加针对该错误的兼容路径：只在原生索引明确报格式错误后，有限读取并校验原视频和原音轨的 SIDX，保留真实初始化范围、分段范围、时间基和偏移，转换为 `isoff-main` / SegmentList 清单。下载仍使用 API 提供的签名地址和原来的原生或加速路径；媒体字节、编码、画质和 HDR 元数据均不改写。支持 SIDX v0/v1 与超过 4 GiB 的偏移；拒绝截断、越界、零时间基、零长度及尚不支持的层级索引。每个播放源只尝试一次；校验失败会停止原生整文件重试并显示错误。

实际 Windows 媒体测试已验证同一公开视频的 HEVC/AAC 原生清单与显式分段清单，后者分别通过原生和加速下载从 12 秒恢复播放。匿名接口只能提供低分辨率轨道，因此这不是对日志中会员 4K 轨道的复现，也不是 Xbox HDR 输出验证。测试者的原日志和临时签名媒体地址只留在本地研究目录，不进入源码导出或测试分发包。

另外使用自行生成的 3840×2160 / 60fps / HEVC Main10 与 AAC 素材，经过真实 Windows HTTP / AdaptiveMediaSource / MediaPlayer 验证原生、加速、兼容索引、兼容索引加速四种组合；全部获得 3840×2160 原生尺寸并推进播放时钟，兼容清单能够从 12 秒恢复。限速在测试源执行，不访问外网。此项验证 4K 十位视频与分段接口，不验证 Xbox HDMI HDR10 信号或同一会员片源。H.264 同样通过四种组合。

## 录屏与修复

录屏 `Desktop 2026.11.17 - 14.25.15.01.mp4` 显示接收约 4～5 MB/s 时可播缓存仍在 0～0.5 秒附近，另一个视频长时间加载。设置打开后开关呈关闭，用户再次打开后保存。仅凭录屏不能确定每次缓存变化是否都是播放源重建。

代码中确认的两个缺口：旧加速器要收齐整个 HTTP Range 后才返回合成响应，慢尾段会阻塞已经下载好的前部数据；播放恢复把任何接收吞吐都当成进展，不能识别「下载很多却长期没有可播进展」。此外，设置一打开立即聚焦开关，没有隔离打开页面的确认键及其松开事件。

- 加速响应改为可顺序读取的流。校验锚点后先返回响应头和已有数据，后续子段按偏移顺序交付；不再等待整个多 MiB 范围完成后才把首字节交给播放器。
- 预读窗口限制未来子段的调度，读端变慢时暂停继续预取。取消/关闭响应会释放等待中的读写任务；头部之后的错误也会传给播放器，当前源随后停用加速尝试。
- 开启加速却连续 12 秒没有明显媒体时钟或可播缓存增长时，保留真实画质和进度重建一次原生下载源。本次观看保持原生，不来回切换；暂停、定位和弹窗期间不触发该恢复。
- 此恢复不写入用户设置。保存的开关继续保持用户选择，重新打开视频后可再试加速。
- 设置增加确认键释放保护：A、Enter、Space 打开页面后，先等待松开，再允许新的按下切换开关；迟到的松开和重复按键不能修改选项。取消不会保存草稿。
- 增加只含布尔状态的设置打开/草稿/保存日志，以及 `acceleration-native-recovery`、加速 `bypass` 诊断，便于区分保存状态与本次播放的临时回退。

## Xbox 复测

1. 安装本轮签名测试包，在帮助页面核对数字安装版本，避免与旧的同名 `1.0.3.1b` 混淆。
2. 打开账号 → 设置，松开打开它的 A 键后观察开关。单纯打开应保持已保存状态；切换后取消，再打开应仍为原状态；明确保存后才改变状态。
3. 同一视频分别关闭/开启加速后重新打开，观察可播缓存与实际播放。重点测试拖动、换画质、视频返回和长时间播放。
4. 若仍出现有接收但无可播进展，应看到一次保留画质的原生恢复，而非持续缓存重置。开关应仍保持原保存状态。
5. 保留完整 `playback-diagnostics.log`，核对等待、下载、源重建和设置日志。实际 Xbox HDR 显示兼容性仍需要同一账号、设备及电视复测。
